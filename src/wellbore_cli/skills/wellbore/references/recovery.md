# 错误与恢复

| 现象 | 操作 |
|---|---|
| 401/403 | 检查 auth status、基地址、Key 是否有效或账户冻结；网页会话限定端点不改用 API Key 强行调用 |
| 422 | 读取 errors 中 path/line/原因，核对井深/垂深和跨块依赖，修改源 YAML 后 validate |
| 429 | quota 查询实际重置时间，按服务返回等待；不要不停重试 |
| 413/415 | 输入不超过 1 MiB；指定正确扩展名或 --input-format |
| 503 队满 | 服务明确拒绝，可稍后人工重试；不能把未知受理结果等同明确拒绝 |
| 查询返回 HTTP 200、status failed | 读取嵌套 error，返回任务失败，不下载、不自动重画 |
| 客户端等待超时/Ctrl-C | 任务可能继续，用同一 JOB_ID 查询/等待 |
| SSE 提前断开 | jobs wait 同一 ID；不 submit |
| POST 超时/断线、没拿到 ID | 查 history，对比名称、时间及规范化输入；避免自动重发 |
| job 404 | 可能重启或完成态淘汰；history 找持久化产物并 download |
| 下载 404 | 检查 archive_id、当前账户、文件名；历史清理可能永久删除产物 |
| 文件已存在 | 换路径；只在用户授权覆盖后使用 --force |
| 代理 8118 不可达 | --no-proxy 或配置当前可用 HTTP 代理 |

任务状态在进程内且有条数上限；历史与产物寿命更长，但会被套餐历史规则或部署清理删除，不能承诺永久保留。历史里没有某条记录不能证明一次未知 POST 未被受理。

REST /api/jobs 没有公开幂等键，与 MCP submit_job 不同。不要添加自创 Idempotency-Key 后宣称已防重，也不要把 MCP 的同步预检口径套给 REST。render 默认先调用公开 normalize 来减少错误提交。

下载逐文件原子落盘，发生中断时已有完整文件可能保留，最终目标不留下半份文件。部分下载失败后可根据成功文件与 history 清单补取缺失文件，不再次绘图。保留 traceId 与恢复命令，但不输出密钥或整份敏感输入。
